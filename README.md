# おくりの地図

長野県東信・群馬県西毛の13自治体を対象にした、葬儀・お墓・終活の情報メディア。31記事、13地域案内、公営の斎場・火葬場の案内（`/facilities/`、現在は佐久平斎場・大星斎場・すみれケ丘聖苑・かぶら聖苑の4ページ）を静的HTMLで配信し、つばさ公益社の関連する公式ページへ案内します。

- 正式ドメイン：`https://okurinochizu.jp/`
- Firebase：`okurinochizu` / Hosting
- GA4：`G-YH2YL4ZMCH`
- 構成：Astro 7、TypeScript、Firebase Hosting、Playwright
- 必要環境：Node.js 22.12以降（検証は24.19）、npm 9.6.5以降

## 開発

```sh
cd /workspace/okurinochizu
npm ci --cache /workspace/.cache/npm
npm run dev
```

Astroは4321番で起動。記事・地域・斎場（`articles`・`regions`・`facilities`）の本文は `src/data/content.json`、出典は `src/data/sources.json`。装飾写真は `src/assets/editorial/`、アイコン類は `public/`、画面は `src/pages/`。秘密情報はソースへ保存しません。

## 検証と公開

```sh
npm run check
npm run build
npm run validate:links
npm test
npm run deploy
```

ビルド時に全HTMLのリンク・構造化データ・サイトマップを確認します。外部リンクは別コマンドで実際に取得します。ブラウザテストは検索、13地域、斎場・火葬場のページ、相談先の表示、要点・早見表・目次、スマートフォンの最初の画面と文字・押せる要素の大きさ、出典の折りたたみ、アクセシビリティ、解析の停止・再開と送客計測を検証します。実行環境にChromiumが必要です。公開ゲートは同じビルドで完了した検証記録を照合します。

ブラウザテストはGoogleへ何も送りません。テスト用のホスト（127.0.0.1）では解析自体が始まりません。`tests/helpers.ts` の `isolateAnalytics` を呼んだテストだけが、テスト専用の印（`window.__okurinochizuAnalyticsTest`。`localhost`・`127.0.0.1` 以外のホストでは無視されます）を読み込み前に立て、Googleのタグを空の代用品に差し替えたうえで解析のコードを動かし、送るはずの内容（`dataLayer`）を照合します。さらに `tests/fixtures.ts` が、すべてのテストで `google-analytics.com` と `googletagmanager.com` への通信を遮断し、印を立てていないページが通信を試みた場合や、通信がブラウザの外へ出た場合はテストを失敗させます。テストは必ず `./fixtures` の `test` を使います（`playwright.config.ts` が確認します）。`GOOGLE_REQUEST_LOG=ファイル名` を付けて実行すると、試みられた通信と結果を1行ずつ記録します。

外部リンクの確認（`npm run validate:links`）は、リンク切れと一時的な障害を分けて扱います（2026-11-20 運営者決定）。

- **失敗（公開を止める）**：4xxの応答すべて（404・410を含む）、および確認用プログラムが追わないURL・転送（https以外や内部ホストへの転送、認証情報らしいパラメーター、転送の繰り返し）。401・403・429は従来どおり `restricted-or-rate-limited`（アクセス制限またはアクセス過多）として記録し、再試行せず、失敗として扱います。
- **警告（公開は止めない）**：どのホストでも、通信エラー・タイムアウト・5xxの応答。408・425・500・502・503・504は1.5秒後に1回だけ再試行し、その結果で判定します。
- 警告は実行の最後に一覧で表示し、`.local/external-link-report.json` の `warnings`（件数）と `warningURLs` に残します。警告だけなら終了コードは0、`status` は `passed` で、公開ゲートも通ります（件数を NOTE として表示）。週次の確認では、この一覧を見て `npm run validate:links -- --retry-failed`（失敗と警告のURLだけを再確認）を実行し、続いている障害はリンク先を確かめます。
- 1件も応答が得られなかった場合は、サイト側の障害ではなく確認する側の通信の問題なので、失敗にします。

Firebase認証は環境設定のsecret `FIREBASE_TOKEN` を使用。独自ドメイン・Search Console・GA4管理画面で必要な操作と、公開後の確認は [公開手順](docs/deployment.md) に記載しています。コードの完成・GitHub保存と、本番公開の成功は別の状態です。

### 相談先の表示（2026-11-10 運営者決定、2026-11-20 地域ページの案内を改定）

つばさ公益社への案内は、次の3種類の要素だけで行います。ビルド検証は種類・個数・位置・順序・文言・リンク先を照合し、これ以外の場所にリンクがあると公開を止めます。

1. **末尾の相談ブロック**（`.referral-card`、計測の placement は `article-end`、ホームは `home-end`）：すべての記事・地域ページ・斎場ページの本文（FAQがあればその直後）と、ホームの末尾に1つ。見出し「葬儀の相談は、つばさ公益社へ」（`referral.label`）、説明は短い1行まで、リンクは「つばさ公益社のページを見る」の1つだけです。淡い地色と罫線1本の四角いブロックで、画像・アイコン・フォームは置きません。
2. **冒頭の相談行**（`.referral-top`、placement は `article-top`）：地域ページ（`/regions/*`）と、カテゴリーが `urgent` の記事（hospital-transport・home-death・first-day）に限り、要点（要点がないページはリード文）の直後に、罫線で区切った行を1つだけ。「葬儀の相談先」の見出し語と、リンク1つです。ほかの記事には置きません。リンクの文言は次のとおりです。
   - `urgent` の記事：「つばさ公益社のページを見る」（従来どおり。`referral.topLabel` は指定できません）。
   - 地域ページ：リンク先のページに実際に載っている内容を示します（`referral.topLabel`、2026-11-20 運営者決定）。使える文言は下の3通りだけで、指定しない地域は「つばさ公益社のページを見る」になります。
     - 「◯◯市の式場と費用を見る（つばさ公益社）」：リンク先がその自治体自身のページ（so-gi.com の `/{県}/{自治体}` 以下）で、その自治体の中にある式場と料金プランが載っている。
     - 「◯◯町周辺の式場と費用を見る（つばさ公益社）」：リンク先は同じくその自治体のページだが、載っている式場はすべて近隣の自治体にある。
     - 「つばさホール◯◯の案内を見る（つばさ公益社）」：リンク先が1つの式場のページ（`…/hall-◯◯`）で、その自治体のページではない。
3. **本文中の一文**（`.referral-inline`、placement は `in-article`）：`inlineReferralAfter` に指定した節の直後に、1ページに1つだけ。「（葬儀について）の相談は、つばさ公益社へ。」という1文で、リンクは社名の1つです。
   - 記事：搬送・亡くなった直後・費用・家族葬など、読者が葬儀社への連絡を決める場面の記事（2026-11-03 運営者決定、従来どおり）。
   - 地域ページ：佐久市（saku）・上田市（ueda）・富岡市（tomioka）の3ページだけ。家族葬を行う会場の節（`family-funeral`）の直後に置きます（2026-11-20 運営者決定。家族葬の会場の節があり、その自治体につばさ公益社の式場がある地域）。安中市（提供エリア外）とほかの地域には置きません。対象を増やすときは、運営者の決定を得てから `scripts/validate-build.mjs` の `regionInlineNotes` と本書を直します。

斎場ページ（`/facilities/*`）に置くのは末尾の相談ブロックだけです。冒頭の相談行と本文中の一文は置きません。リンク先と見出しは、その施設が立つ自治体の地域ページ（`facility.region`）の `referral` をそのまま使い、施設のデータには相談先を持たせません（佐久平斎場は佐久市のページと同じ `https://so-gi.com/nagano/saku`）。`utm_content` は `{施設のslug}-article-end`、GA4 の `region` は施設が立つ地域の slug です。

したがって1ページの相談リンクは、地域ページが2つ（佐久市・上田市・富岡市は3つ）、`urgent` の記事が2〜3つ、そのほかの記事が1〜2つ、斎場ページが1つ、ホームが1つ、それ以外のページ（斎場の一覧 `/facilities/` を含む）は0です。並ぶ順は、冒頭の相談行、本文中の一文、末尾の相談ブロックです。リンク先は各ページの `referral.href`（ホームは施設案内）で、どの要素も同じ宛先に `utm_content={ページ}-{placement}` を付け、GA4の `provider_referral_click` に placement とページを送ります。

### 記事・地域ページの構成

上から、パンくず、H1、要点「まず知っておきたいこと」、（該当ページのみ）冒頭の相談行、（地域ページと斎場ページ）早見表、目次、ヘッダー画像1枚、本文の節、FAQ、末尾の相談ブロック、出典の折りたたみ、関連記事・地域の順に並べます。

- **要点**（`keyPoints: string[]`、記事・地域とも任意）：3〜5個の短い文。あるページは淡い地色のブロックに箇条書きで表示し、リード文は表示しません。ないページは従来どおりリード文（`lead`）を表示します。
- **早見表**（`quickFacts: { label, value, href? }[]`、地域は任意、斎場ページは必須）：火葬場、休業日、火葬料、死亡届の窓口、窓口の電話、葬祭費などを、項目名と値の2列の罫線表で示します。`href` を付けると値全体がリンクになり、公的窓口の電話は `tel:` + 数字、案内ページはそのページの `sources` に登録したURLに限ります。
- 要点と早見表に書けるのは、そのページの本文で確認済みの事実だけです。新しい事実・事業者名は加えず、`updatedAt` も変えません。ビルド検証は、要点・早見表に出てくる数字（金額・時刻・電話番号）がそのページの本文にあること、電話リンクの番号が表示と一致することを確かめます。
- **目次**：節（h2）とFAQから自動で作ります。1023px以下では閉じた `<details>`（見出し「目次」）、1024px以上では本文の右に追従する脇欄として表示します。同じ一覧を2つ出力してCSSで片方だけ表示するため、スクリプトなしで動きます。

記事一覧・関連記事・検索結果は、短い記事タイトルとあらすじだけを、罫線で区切った行として表示します（行全体がリンク）。タイトルの「｜」以降の副題、各記事のカテゴリーラベル・番号は一覧に重ねません。カテゴリーのメニューやタグは表示せず、ヘッダーは「記事一覧」「地域の案内」に統一します。ヘッダーに検索へのリンクは置きません。ホームと記事一覧では、記事を「葬儀の前後／費用とお金／手続き／お墓と終活」の4つにまとめます（`src/data/site.ts` の `needs`。既存の6カテゴリーをどれか1つに割り当て、ホームに出す3本は `featured` で指定）。

ヘッダーはPCで高さ64pxの固定表示、760px以下では高さ60pxで下へ読むと隠れ、上へ戻ると表示します。メニュー展開中とキーボード操作中は表示を保ち、Escapeでメニューを閉じられます。スクロールの微小な揺れでは切り替えず、動きを減らす設定を尊重します。記事内の移動先とスキップリンクはヘッダーに隠れないよう調整します。メディア紹介ページの「地域の案内を読む」は削除し、プライバシーへのリンクは保持します。

末尾の相談ブロックは、本文とFAQがある場合はその直後、関連記事・地域案内の前に置きます（相談ブロックと関連記事の間に置けるのは後述の出典の折りたたみだけです）。`article-end` のクリック計測は本文末尾の配置を表します。本文リンクは説明の続きを読みたい箇所に設け、記事ごとの個数を固定しません。同じリンク先を繰り返さず、メニューやタグは追加しません。インラインリンクは `Section.paragraphLinks`、表のリンクは `Section.table.links` で管理し、本文をHTML文字列に変換せず、一意な語句をリンク化します。構成変更で統合した見出しの旧アンカーは `Section.aliases` に残します。

制度の金額には保険・自治体・申請者・期限を添えます。国保の葬祭費は13地域を掲載し（小海町は町の案内に金額がないため金額を書かず、窓口を案内。青木村は村の国民健康保険条例の20,000円を記載）、一次情報で確かめられた期限だけ数字を記載します。協会けんぽの埋葬料と埋葬費の起算日は区別します。必要な申請案内へは本文・表から直接進めます。出典と確認日は、後述の折りたたみ1つだけで示します。

### 斎場・火葬場のページ（`/facilities/`、2026-11-23 追加）

公営の斎場・火葬場ごとに1ページを置きます（`/facilities/<slug>/`、最初のページは `sakudaira-saijo`＝佐久平斎場、2026-11-24 に `oboshi-saijo`＝大星斎場、2026-11-25 に `sumiregaoka-seien`＝すみれケ丘聖苑、2026-11-26 に `kabura-seien`＝かぶら聖苑を追加）。施設名での検索（予約・料金・アクセスなど）に、公式資料で確かめた内容だけで答えるページです。一覧は `/facilities/`。

- **構成**：地域ページと同じ部品を同じ順に並べます。パンくず（ホーム／斎場・火葬場の案内／施設名）、H1、要点、早見表、目次、ヘッダー画像1枚、本文の節、末尾の相談ブロック、出典の折りたたみ、「この斎場を使う地域の案内」（`regions` の地域ページ）、「関連記事」（`related`）。冒頭の相談行・本文中の一文・FAQはありません。新しい見た目の部品は作りません。
- **データ**（`content.json` の `facilities`、型は `Facility`）：`slug`・`name`・`region`（施設が立つ自治体の地域 slug。相談ブロックはこの地域の `referral`）・`regions`（その施設を使う地域 slug の一覧。検索の地域絞り込みと相互リンクに使う）・`postalCode`／`prefecture`／`locality`／`street`／`phone`（運営者が公表している所在地と電話）・`pageTitle`（施設名で始める）・`heading`・`description`・`summary`（一覧に出す1行）・`lead`・`keyPoints`・`quickFacts`・`sections`・`sources`・`related`・`publishedAt`・`updatedAt`。
- **本文の決まり**：事実はすべて運営者・自治体・例規集の一次資料で当日に確かめ、`sources` に登録します。公式に確かめられないこと（最寄り駅やICからの所要時間、駐車場の台数など）は書かず、読者が誤解しそうな箇所にだけ「公式の案内には書かれていない」と記します。所要時間や距離を自分で計算しません。事業者名、「監修」、口コミ・評価・レビュー、体験談は載せません（利用案内の末尾にある霊柩運送業者の一覧も転記しません）。本文のリンクは、記事（`/guides/*`）、その施設を使う地域ページ（`regions` にある `/regions/*`）、そのページの `sources` に登録した公式ページだけです。
- **表**：使用料の表は「区分／住民／住民以外」のように短いセルの3列にし、長い条件は表の下の文（`note`）に書きます。斎場ページの表は390px・320pxでも横スクロールなしで収まります（`.article-shell--facility`）。
- **構造化データ**：地域ページと同じ `WebPage` に、`about` として `Crematorium`（施設名・公表されている住所・電話だけ）を付けます。評価・レビュー・営業時間などは付けません。
- **画像**：1ページ1枚（`facility-<slug>-header.webp`）。実在の建物を描かず、施設の写真に見せない風景にします。一覧（`/facilities/`）には画像・相談ブロック・出典の折りたたみを置きません。
- **リンクの入口**：地域一覧（`/regions/`）の地域索引の下の「斎場・火葬場の案内」、各地域ページ末尾の関連ナビゲーション「この地域の斎場・火葬場」（その地域が `regions` に入っている施設だけ。施設のデータから自動で出し、地域ページの本文・データ・`updatedAt` は変えません）、検索、サイトマップ、`llms.txt`。ホームとヘッダー・フッターには置きません。
- **ビルド検証**：地域ページと同じ検証（要点・早見表の数字が本文にあること、出典の登録、相談リンクの種類・位置・宛先、フッター、画像1枚、出典の折りたたみ、目次）に加えて、相談ブロックが `region` の地域と同じ宛先であること、電話リンクが `phone` の1つだけであること、所在地と電話が本文にあること、構造化データが登録内容と一致すること、地域ページ・地域一覧・施設一覧からのリンクが施設データどおりであることを確かめます。

施設を追加する手順：(1) 公式ページを当日取得して `src/data/sources.json` に登録・`checkedAt` を更新、(2) `content.json` の `facilities` に1件追加、(3) `src/assets/editorial/unique/facility-<slug>-header.webp` を1回だけ生成して `docs/editorial-image-manifest.json` と `docs/editorial-images.md` に記録、(4) H1を文節で折り返すなら `src/data/heading-parts.ts` に1行、(5) `tests/search.spec.ts` の件数を直し、`npm run check && npm run build && npm run validate:links && npm test`。ルート・一覧・地域ページからのリンク・サイトマップ・検索・`llms.txt` はデータから自動で出ます。

### デザインの原則（2026-11-10 全面改訂）

読者は50〜70代が中心で、スマートフォンで急いで読みます。印刷された地域の案内冊子のように、文字の大きさ・罫線・余白・揃えで構造を示します。

- 本文は16px以上（761px以上では17px）、行間は1.85〜1.9。一覧のあらすじ・パンくず・出典などの補助的な文字も14px以上。リンクやボタンなどの押せる要素は高さ44px以上（本文の文中リンクと、索引を補う模式地図上の地名を除く）。配色はWCAG AAのコントラストを満たします。
- 色は、あたたかい紙色の地・深緑の文字・さび色の差し色の平塗りだけです。影、グラデーション、ぼかし、角丸（2pxを超えるもの）、浮き上がるホバー、丸や四角に入れたアイコン、絵文字、英字の小見出しは使いません。アイコンはメニューと細い矢印だけです。
- 見出しと地名は明朝（端末のシステムフォント）、本文・数字・表はゴシック。Webフォントは読み込みません。ダークモードはありません。
- まとまりは、太い罫線1本と見出し、行を区切る細い罫線、淡い地色の四角いブロックで示します。角丸と影のついたカードを並べる構成にはしません。

ホームには斎場ページへのリンクを置きません（最初の画面を変えないため。入口は地域一覧と地域ページです）。ホームの最初の画面（390×844）には、短い見出し、「いま、家族が亡くなった方へ」（hospital-transport・home-death・first-day・funeral-flow への番号付きの4行）、「地域から探す」（県別の13自治体の索引）を収めます。写真はスマートフォンではその後ろに置き、761px以上では見出しの右に並べます。地域の模式地図は761px以上で索引の横に表示し、地域ページでは「ほかの地域」にそのページの自治体を強調して表示します。続いて「記事から探す」に4つのまとまりを各3本、末尾に相談ブロックを置きます。

記事・地域ページは1カラムで読み、1024px以上では右に目次の脇欄が付きます。記事一覧・地域一覧・検索は同じ行と索引の形を使います。旧カテゴリーURLは記事一覧へ301転送し、サイトマップには掲載しません。見出しの添え文、画像下の説明文、差し込み帯、著者・公開日・更新日の表示、記事末尾の定型注意文は置きません。フッターには、運営者情報（見出しのリンク・会社名・住所・公式サイト）と、その下の罫線で区切った1行に「このメディアについて」（`/about/`）と「プライバシー」（`/privacy/`）のリンクを置きます（2026-11-20 運営者決定。「フッターには運営者情報だけ」としていた従来の決まりは廃止）。2つのリンクは運営者情報の見出しと同じ太さの文字だけで示し、アイコン・角丸の枠・ボタンにはしません。フッターにこれ以外のリンクは置かず、ビルド検証が全ページで照合します。プライバシーページへのリンクは「このメディアについて」の本文にも残します。

アクセス解析の説明と停止・再開ボタンはプライバシーページに集約します。初期設定は有効ですが、保存済みの停止設定を優先します。解析を始めるのは、ページのホスト名が `okurinochizu.jp` と一致するときだけです（2026-11-20 運営者決定）。`localhost`・`127.0.0.1`・`*.web.app`・`*.firebaseapp.com` などほかのホストでは、Googleのタグを読み込まず、ページ閲覧もクリックも送りません（停止・再開の表示と保存は同じように動きます）。フッターや他のページに説明やポップアップを置きません。Google Analytics管理画面の拡張計測「サイト内検索」は無効にしてください。送信URLの検索パラメーターは除き、検索内容をイベントへ含めません。

風景・植物・小物の装飾用イメージ写真は、1ページに1枚だけ使います（ホーム、記事、地域案内、斎場ページ、記事一覧・地域一覧、メディア紹介。斎場の一覧 `/facilities/` には置きません）。記事・地域ページでは、要点・早見表・目次の後、本文の前にヘッダー画像を1枚置き、スマートフォンでは横長（2:1）に切り抜いて遅延読み込みにします。本文中の2枚目（interlude）は表示しません。各掲載箇所に専用画像を割り当て、全サイトで使い回しません。ビルド検証は、1ページ1枚であることと画像の重複がないことを確かめ、違反すると公開を止めます。表示しなくなった interlude 画像のファイルと制作記録はリポジトリに残しています。画像には説明文・キャプション・ラベルを付けず、実在する施設や地域の撮影写真として扱いません。原本と配置方針は [画像の制作記録](docs/editorial-images.md) を参照してください。Astroが表示幅別のWebPを生成し、寸法と表示比率を先に確保します。

具体的な金額は「50,000円」のように半角数字・3桁区切り・円単位で記載し、表と本文・地域案内で同じ形式を使います。

地域一覧は県別に地域名のリンクだけを罫線の索引として表示し、各地域の補足説明は置きません。その下に「斎場・火葬場の案内」として、斎場ページの一覧（施設名と1行の説明）と `/facilities/` へのリンクを置きます。

葬儀場への送客はつばさ公益社に限定します。公開ページでは関係性や紹介報酬の説明を表示しません（例外は後述の運営者情報ページのみ）。最低価格を地域相場や総額として扱いません。

出典と確認日は、記事（`/guides/*`）・地域（`/regions/*`）・斎場（`/facilities/*`）のページに限り、末尾の相談ブロックの直後、関連記事・地域案内の前に、閉じた状態の `<details class="source-note">` を1つだけ置いて示します（2026-11-10 運営者決定）。見出しは「出典と確認日（N件・最終確認 YYYY年M月D日）」の1行で、本文より小さい控えめな文字（14px）にし、操作を促す見た目にしません。開くと、そのページの `sources` に登録した出典の題名（公式ページへの通常のリンク）と「確認日 YYYY年M月D日」を、登録順の簡潔なリストで表示します。件数・日付は `src/data/sources.json` の登録内容と `checkedAt` だけから作り、対応づけや日付を補いません。つばさ公益社のページ（相談リンク以外で送客リンクを増やさないため）と競合する紹介サイト（リンクしないため）は一覧に含めず、該当する出典がないページでは折りたたみ自体を置きません。ホーム・一覧（斎場の一覧を含む）・メディア紹介・運営者情報・プライバシー・検索には置かず、本文中に出典一覧の見出しや大きな枠、画像・アイコンは追加しません。ビルド検証は、この要素の有無・位置・閉じた初期状態・件数・最終確認日・各リンクと確認日を登録内容と照合します。

運営者情報は `src/data/operator.json` で管理します。全ページのフッターに「運営者情報」の見出し（`/operator/` へのリンク）、会社名、住所、公式サイトを掲載し（その下に「このメディアについて」「プライバシー」へのリンク）、「このメディアについて」の本文には重ねて掲載しません。運営者の公式リンクは葬儀相談の送客計測に含めません。

`/operator/`（運営者情報）は、運営会社・代表者・編集の方針と、つばさ公益社との関係を示すページです。事業者名・関係性の説明・出典や確認日への言及を本文に含めてよいのはこのページだけで、ビルド検証もこのページに限って許可します（記事・地域ページの `.source-note` に限り、出典と確認日の表示を許可します）。出資に関する一文は `#relationship` の要素にまとめます。OrganizationのJSON-LDはこのページにのみ置き、記事・地域ページの末尾に関係性の説明やリンクを追加しません。
